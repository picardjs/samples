# Picard.js with Angular SSR

An Angular 19 application with server-side rendering and hydration, set up as the Angular CLI generates it (`@angular/ssr` with Express). Picard.js renders micro frontends on the server too, and resumes them in the browser.

## What Picard.js Does Here

Angular renders the page on the server and hydrates it in the browser. Picard.js adds a second step on the server: it takes the HTML produced by Angular and renders the micro frontends into the `pi-component` elements. In the browser, Picard.js's islands script resumes them:

- `pi-ssr-html` is rendered on the server and *hydrated* in the browser. Its button works without being rendered again.
- The other micro frontends of the demo feed can only render in the browser, so they are marked with `server="none"` and rendered there.

Angular's hydration isn't affected: Angular doesn't own the content of the `pi-component` elements, so it doesn't compare or replace it.

## How It Is Integrated

**1. Decorate Angular's response.** [`src/server.ts`](./src/server.ts) is the Express server generated by the CLI. It initializes `picard-js/node` and passes each HTML response of the Angular engine through `picard.decorate`:

```ts
const picard = initializePicard({
  feed: 'https://feed.piral.cloud/api/v1/microfrontends/picard-demos',
  interactive: true,
  scriptUrl: '/picard/picard.js',
});

async function decorate(response: Response) {
  if (!response.headers.get('content-type')?.includes('text/html')) {
    return response;
  }

  const html = await picard.decorate(await response.text());
  const headers = new Headers(response.headers);
  headers.delete('content-length');
  return new Response(html, { status: response.status, statusText: response.statusText, headers });
}

app.use('/**', (req, res, next) => {
  angularApp
    .handle(req)
    .then(async (response) => (response ? writeResponseToNodeResponse(await decorate(response), res) : next()))
    .catch(next);
});
```

`interactive: true` makes Picard.js emit the state and the islands script, and `scriptUrl` says where the browser gets it.

**2. Serve the islands script.** Also in `src/server.ts`:

```ts
app.get('/picard/:file', (req, res) => {
  const content = getIslandsFile(req.params.file);

  if (content === undefined) {
    res.sendStatus(404);
  } else {
    res.type('text/javascript').send(content);
  }
});
```

**3. Reserve the places for styles and scripts.** [`src/index.html`](./src/index.html) contains two `pi-part` elements, which `decorate` replaces with the styles of the micro frontends and with the state and islands script:

```html
<head>
  <!-- ... -->
  <pi-part name="style"></pi-part>
</head>
<body>
  <app-root></app-root>
  <pi-part name="script"></pi-part>
</body>
```

**4. Use the components.** [`src/app/app.component.html`](./src/app/app.component.html) (the component declares `CUSTOM_ELEMENTS_SCHEMA`):

```html
<pi-component name="column" source="mf-simple-html" server="none"></pi-component>
<pi-component name="column" source="nfsimplehtml" server="none"></pi-component>
<pi-component name="counter" source="pi-simple-html" server="none"></pi-component>
<pi-component name="ssr-counter" source="pi-ssr-html" data='{"start":5}'></pi-component>
```

## Good to Know

- Decorating after Angular, rather than inside an Angular component, keeps the integration in one place and works for every route. The trade-off is that the response is buffered, which Angular's engine does anyway.
- The Angular dev server (`ng serve`) uses the same `server.ts`, so the micro frontends are server-rendered during development too.
- Rendering Native Federation micro frontends (ES modules) on the server requires Node.js to run with `--experimental-vm-modules`. The micro frontends of this page don't need it. See the [Bun](../../bun/ssr/) and [Deno](../../deno/ssr/) samples, which support it without a flag.

## Running

```sh
npm install
npm start
```

Then open `http://localhost:4200`. For production:

```sh
npm run build
npm run serve:ssr:ssr
```

Then open `http://localhost:4000`.

See [Angular SPA](../spa/) for the client-only variant.
